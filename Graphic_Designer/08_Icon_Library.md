# CARIVIX AI — Icon Library

## 1. Overview

The CARIVIX AI Icon Library was designed as a **centralized visual system** for the product interface, documentation, presentations, and other digital assets.

### Purpose

To provide a **consistent set of icons** for common CARIVIX functions and product modules while maintaining the same visual language throughout the application.

### Icon Style

The library follows an:

- **Outline-based** icon style
- **Consistent sizing**
- **Consistent stroke treatment**
- **Rounded forms**
- **Simplified visual shapes**

## 17. Icon Grid & Base Specification

The icon library is based on a defined technical specification:

> **24px • 2px Stroke • Rounded • Outline Style**

### Base Specifications

| Specification | Value | Purpose |
|---|---|---|
| **Base Size** | 24 × 24 px | Consistent baseline for interface icons; aligns with other UI components |
| **Stroke Width** | 2 px | Maintains consistent visual weight |
| **Corner Treatment** | Rounded | Creates a softer and more approachable interface appearance |
| **Icon Style** | Outline-based (not filled) | Creates a unified appearance across categories |

## 20. Usage Guidelines

The icon board provides specific usage guidance.

### Size Guidelines

| Context | Size |
|---|---|
| Navigation and buttons | **24 px** |
| Cards and presentations | **32–48 px** |

> This creates a distinction between:
> - **Functional interface icons** (24 px)
> - **Larger visual / presentation usage** (32–48 px)

### Interface Usage

| Usage | Size |
|---|---|
| Standard application UI | 24 px |
| Larger feature cards or presentation visuals | 32–48 px |

> This allows the same icon system to **scale while maintaining its visual identity**.

---

## 21. Stroke & Style Guidelines

The board also establishes **three main style rules**:

| # | Rule | Description |
|---|---|---|
| 1 | **2 px Outline Stroke** | All icons maintain the same basic stroke treatment |
| 2 | **Rounded Corners** | Rounded corners are consistently applied to create a unified appearance |
| 3 | **Consistent Style Across All Icons** | Icons should visually belong to the same family regardless of category |

> This is particularly important when icons from different categories **appear together on the same dashboard or screen**.

## 24. Why the Library Was Structured This Way

Instead of creating random icons whenever a new screen required one, the library establishes a **centralized visual vocabulary**.

### Function-to-Category Mapping

```
AI Features        → AI & Intelligence Icons
Analytics          → Dashboard & Analytics Icons
Reports            → Documents & Reports Icons
GIS                → Global & Location Icons
Security           → Security Icons
System Actions     → Interface & Actions Icons
```

> This makes the **icon selection process faster** and keeps the product **visually consistent**.

---

## 25. Icon Library Workflow

The design process can be represented as:

```
Identify Product Functions
↓
Group Icons by Function
↓
Define 24px Grid
↓
Set 2px Stroke
↓
Apply Rounded Outline Style
↓
Create Individual Icons
↓
Assign Functional Names
↓
Organize into Categories
↓
Define Usage Sizes
↓
Review Visual Consistency
↓
Create Reusable Icon Library
```
