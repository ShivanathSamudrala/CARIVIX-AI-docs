# Grounded Responses

## 1. Overview

Grounded responses are responses generated by the CARIVIX AI/RAG Engine using information retrieved from the project's indexed documents rather than relying only on the Large Language Model's internal knowledge.

In a Retrieval-Augmented Generation architecture, the LLM receives **two important inputs**:

1. The user's question
2. Relevant information retrieved from the document knowledge base

The retrieved information acts as the **evidence** or **context** used during response generation.

### Fundamental CARIVIX Flow

```text
User Query
    ↓
Query Processing
    ↓
Embedding Generation
    ↓
FAISS Retrieval
    ↓
Relevant Document Chunks
    ↓
Prompt Construction
    ↓
LLM Inference
    ↓
Grounded Response
```

The objective is to ensure that generated responses remain **connected to the information available in the indexed knowledge base**.

> Grounding is particularly important for document intelligence because a generative model can produce fluent responses even when the required information is not present in its input context.

A grounded-response mechanism therefore introduces a controlled relationship between:

```text
Retrieved Evidence → Prompt → Generated Answer
```

---

## 2. Grounding Architecture

The CARIVIX grounding architecture begins when the user submits a query.

1. The query is processed and converted into an embedding representation using the configured embedding model
2. The embedding is compared against vectors stored in the FAISS index
3. The retrieval system identifies the most relevant document chunks according to vector similarity
4. The retrieved chunks are passed to the prompt-template layer
5. The prompt template combines:
   - System Instructions
   - Retrieved Context
   - User Question
   - Grounding Instructions
6. The resulting prompt is sent to the LLM inference layer
7. The model generates a response based on the supplied context
8. The response can pass through validation or evaluation logic before being returned to the user

### Architectural Flow

```text
Knowledge Documents
    ↓
Document Processing
    ↓
Chunking
    ↓
Embedding Generation
    ↓
FAISS Vector Index
    ↓
Query
    ↓
Query Embedding
    ↓
Vector Retrieval
    ↓
Relevant Context
    ↓
Prompt Template
    ↓
LLM
    ↓
Generated Response
    ↓
Grounding Validation
    ↓
Final Response
```

> **Important architectural principle:** The retrieval layer supplies the **factual context**, while the LLM performs **language understanding and response generation**.

## 3. Grounded Response Generation Workflow

The grounded-response workflow contains several technical stages.

### Step 1 — User Query

The user provides a natural-language question.

**Example:**

> What factors affected the economic trend during the analyzed period?

The question becomes the input to the retrieval pipeline.

### Step 2 — Query Embedding

The query is converted into a numerical vector using the configured embedding model.

The CARIVIX architecture uses a **Sentence Transformers** embedding model, with the documented **all-MiniLM-L6-v2** configuration producing **384-dimensional embeddings**.

The vector representation allows **semantic similarity** to be calculated between the query and indexed document chunks.

### Step 3 — Vector Retrieval

The query vector is passed to **FAISS**.

FAISS searches the vector index and returns the highest-ranked matching chunks.

The CARIVIX RAG configuration uses a **top-K retrieval** approach, with the documented default retrieval value of:

```text
K = 5
```

The retrieved chunks form the **evidence available to the generation layer**.

### Step 4 — Context Assembly

The retrieved chunks are combined into a context block.

**Conceptually:**

```text
Context =
    Chunk 1
    + Chunk 2
    + Chunk 3
    + Chunk 4
    + Chunk 5
```

Relevant metadata may also be included when required.

### Step 5 — Prompt Construction

The context is inserted into the grounded-response prompt.

**Example:**

```text
You are a CARIVIX AI assistant.

Use the following retrieved information to answer the question.

Retrieved Context:
{context}

Question:
{question}

Instructions:
- Use the retrieved information as the primary evidence.
- Do not introduce unsupported facts.
- If the context is insufficient, state that clearly.

Answer:
```

### Step 6 — LLM Inference

The completed prompt is passed to the LLM through the inference layer. The model generates a natural-language response based on the question and supplied context.

### Step 7 — Response Validation

The generated response can be evaluated for:

- Relevance
- Groundedness
- Factual consistency
- Context usage
- Unsupported claims
- Completeness

The final response is then returned to the user.

## 4. Grounding Mechanism

**Grounding** means that the generated response should be supported by information available in the retrieved context.

### Simplified Relationship

```text
Grounded Response ≈ User Query + Retrieved Evidence + LLM Generation
```

The LLM remains responsible for generating natural language, but the **retrieved context provides the information** that should support the answer.

### Example

**Retrieved context:**

```text
Economic growth increased during the first period.
Inflation increased during the following period.
Consumer demand subsequently decreased.
```

**User asks:**

> What happened to consumer demand?

**Grounded response:**

> Consumer demand decreased during the subsequent period.

The answer **directly reflects the retrieved information**.

### Ungrounded Example

**Ungrounded response:**

> Consumer demand decreased because interest rates increased by 3%.

If the retrieved context **does not contain** the interest-rate information, the additional statement is **unsupported**.

> Therefore, grounding instructions should encourage the model to **avoid adding information that cannot be supported by the retrieved evidence**.

## 6. Handling Insufficient or Missing Context

A critical component of grounded responses is handling situations where the retrieval layer does **not** provide enough information.

The system should **not** assume that every user question can be answered from the indexed knowledge base.

### Example

**User:**

> What was the company's revenue in 2026?

**Retrieved Context:**

> No relevant revenue information was retrieved.

A controlled response should **communicate that the available context is insufficient**.

### Conceptual Logic

```text
IF relevant_context_available:
    generate_answer_using_context
ELSE:
    return_insufficient_information_response
```

### Suitable Instruction

```text
If the retrieved context does not contain enough information
to answer the question, do not invent an answer.
State that the available information is insufficient.
```

> **This mechanism is important because a highly fluent LLM response is not necessarily a grounded response.** The system should prioritize **evidence availability** over **response completeness**.

## 7. Grounded Response Validation and Evaluation

Grounded responses should be evaluated systematically as part of the CARIVIX AI evaluation process.

### Evaluation Dimensions

| Dimension | Purpose |
|---|---|
| **Relevance** | Response should directly answer the user's question |
| **Groundedness** | Response should be supported by information contained in the retrieved context |
| **Factual Consistency** | Claims made by the response should remain consistent with the retrieved evidence |
| **Context Utilization** | Response should actually use relevant retrieved information |
| **Unsupported Claim Detection** | Evaluation process should identify claims that cannot be supported by the retrieved context |
| **Completeness** | Answer should contain the relevant information available in the retrieved evidence without unnecessarily introducing unrelated information |

### Simplified Evaluation Pipeline

```text
Retrieved Context
    ↓
Generated Response
    ↓
Compare Response Against Context
    ↓
Check Claims
    ↓
Evaluate Groundedness
    ↓
Evaluate Relevance
    ↓
Evaluate Factual Consistency
```

> Grounding evaluation should ideally use a **fixed test dataset** containing representative user queries and expected evidence. This allows **prompt changes, retrieval changes, and model changes** to be evaluated consistently.

## 8. Grounded Response Lifecycle and Failure Handling

The grounded-response lifecycle begins with **document ingestion** and ends with **response delivery**.

### Complete Lifecycle

```text
Documents
    ↓
Document Loading
    ↓
Text Chunking
    ↓
Embedding Generation
    ↓
FAISS Index
    ↓
User Query
    ↓
Query Embedding
    ↓
Similarity Search
    ↓
Retrieved Context
    ↓
Prompt Construction
    ↓
LLM Generation
    ↓
Grounding Evaluation
    ↓
Response
```

### Major Failure Conditions

| # | Failure | Impact | Expected Behavior |
|---|---|---|---|
| 1 | **Retrieval Failure** — relevant documents are not retrieved | LLM receives insufficient evidence | Fallback to insufficient-context response |
| 2 | **Low-Relevance Retrieval** — retrieved chunks are related but do not contain required information | Generated answer may be incomplete or unsupported | Flag for retrieval-quality review |
| 3 | **Context Overload** — too much retrieved content is supplied to the model | Important information may become difficult to prioritize | Reduce top-K or improve chunking |
| 4 | **Unsupported Generation** — LLM introduces information not contained in retrieved context | Answer becomes less grounded | Apply grounding validation |
| 5 | **Missing Information** — required information does not exist in the indexed knowledge base | N/A | System should clearly indicate insufficient information rather than fabricate an answer |

## 9. Conclusion

Grounded responses are a **core component** of the CARIVIX AI/RAG Engine because they establish a controlled connection between retrieved knowledge and LLM-generated responses.

### Complete Process

```text
User Query
    ↓
Embedding
    ↓
FAISS Retrieval
    ↓
Relevant Context
    ↓
Grounded Prompt
    ↓
LLM Generation
    ↓
Grounding Validation
    ↓
Final Response
```

### Primary Objective

> The primary objective is **not simply to generate a fluent answer**. The objective is to generate an answer that is:
> - **Relevant**
> - **Context-supported**
> - **Resistant to unsupported information**

### Technical Foundation

The combination of:

| Component | Role |
|---|---|
| **Sentence Transformers** | Semantic representation |
| **FAISS** | Vector retrieval |
| **Structured Prompt Templates** | Context injection |
| **LLM Inference Layer** | Response generation |

…provides the technical foundation for **grounded response generation** in CARIVIX.

### Architectural Principle

> **Grounding should therefore be treated as an end-to-end architecture concern** covering:
> - Retrieval quality
> - Context construction
> - Prompt design
> - Model generation
> - Response evaluation
>
> …rather than as a single instruction inside the LLM prompt.
