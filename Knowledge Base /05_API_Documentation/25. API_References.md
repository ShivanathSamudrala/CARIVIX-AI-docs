## 1. Overview

This document lists every available API endpoint, what it does, what it expects as input, and what it returns. All endpoints follow a consistent error reporting pattern.

**Base URL:** `http://localhost:8000`

---

## 2. API Endpoints Summary

| **Method** | **Endpoint** | **Purpose** |
|------------|--------------|-------------|
| GET | `/health` | Confirm API is running |
| GET | `/sources` | List configured data sources |
| POST | `/process` | Process data using a named profile |
| POST | `/validate` | Validate data against defined rules |
| POST | `/store` | Write records to a database table |
| GET | `/retrieve/{table_name}` | Read records from a table |
| POST | `/pipeline` | Process and store in one request |

---

## 3. GET /health

**Purpose:** Confirms that the API is running.

**Input:** None

**Output:**
```json
{
  "status": "ok"
}
```

---

## 4. GET /sources

**Purpose:** Lists every configured data source, organized by category.

**Input:** None

**Output:**
```json
{
  "csv": ["source1", "source2"],
  "excel": ["source1", "source2"],
  "json": ["source1", "source2"],
  "api": ["source1", "source2"]
}
```

| **Field** | **Description** |
|-----------|-----------------|
| csv | List of configured CSV source names |
| excel | List of configured Excel source names |
| json | List of configured JSON source names |
| api | List of configured API source names |

---

## 5. POST /process

**Purpose:** Runs a set of records through a named processing profile and returns the result.

**Input:**
```json
{
  "records": [
    {
      "field1": "value1",
      "field2": "value2"
    }
  ],
  "profile_name": "company_financials"
}
```

| **Parameter** | **Type** | **Required** | **Description** |
|---------------|----------|--------------|-----------------|
| records | List of objects | Yes | Records to process |
| profile_name | String | Yes | Processing profile to apply |

**Available Profile Names:**
- `company_financials`
- `economic_indicators`

**Note:** Additional profiles can be added without changing any code.

**Output:**
```json
{
  "row_count": 10,
  "columns": ["column1", "column2", "column3"],
  "processed_records": [
    {
      "column1": "value1",
      "column2": "value2"
    }
  ]
}
```

| **Field** | **Description** |
|-----------|-----------------|
| row_count | Number of rows in the result |
| columns | List of column names in the result |
| processed_records | The processed records themselves |

---

## 6. POST /validate

**Purpose:** Checks a set of records against a defined set of rules without modifying the data.

**Input:**
```json
{
  "records": [
    {
      "field1": "value1",
      "field2": "value2"
    }
  ],
  "rules": [
    {
      "field_name": "field1",
      "data_type": "string",
      "required": true,
      "min_value": null,
      "max_value": null
    },
    {
      "field_name": "field2",
      "data_type": "number",
      "required": true,
      "min_value": 0,
      "max_value": 100
    }
  ]
}
```

| **Parameter** | **Type** | **Required** | **Description** |
|---------------|----------|--------------|-----------------|
| records | List of objects | Yes | Records to validate |
| rules | List of objects | Yes | Validation rules to apply |

**Rule Fields:**

| **Field** | **Type** | **Description** |
|-----------|----------|-----------------|
| field_name | String | Name of the field to validate |
| data_type | String | Expected data type (string, number, date) |
| required | Boolean | Whether the field is required |
| min_value | Number | Optional minimum value for numeric fields |
| max_value | Number | Optional maximum value for numeric fields |

**Output:**
```json
{
  "total_rows_checked": 100,
  "rows_passed": 95,
  "duplicate_rows_found": 2,
  "missing_values": {
    "field1": 3,
    "field2": 0
  },
  "rows_failed": 5,
  "overall_result": true
}
```

| **Field** | **Description** |
|-----------|-----------------|
| total_rows_checked | Total number of rows checked |
| rows_passed | Number of rows that passed all rules |
| duplicate_rows_found | Number of duplicate rows found |
| missing_values | Count of missing values for each field |
| rows_failed | Number of rows that failed validation |
| overall_result | True if entire dataset passed, false otherwise |

## 7. POST /store

**Purpose:** Writes a set of records into a named database table.

**Input:**
```json
{
  "table_name": "my_table",
  "records": [
    {
      "field1": "value1",
      "field2": "value2"
    }
  ]
}
```

| **Parameter** | **Type** | **Required** | **Description** |
|---------------|----------|--------------|-----------------|
| table_name | String | Yes | Name of the target table |
| records | List of objects | Yes | Records to write |

**Output:**
```json
{
  "rows_written": 10
}
```

| **Field** | **Description** |
|-----------|-----------------|
| rows_written | Number of rows successfully written |

---

## 8. GET /retrieve/{table_name}

**Purpose:** Reads records back from a named table.

**Input (Path Parameter):**

| **Parameter** | **Type** | **Required** | **Description** |
|---------------|----------|--------------|-----------------|
| table_name | String | Yes | Name of the table to read from |

**Input (Query Parameters):**

| **Parameter** | **Type** | **Required** | **Description** |
|---------------|----------|--------------|-----------------|
| field | String | No | Field name to filter by |
| value | String | No | Value to filter by |
| limit | Integer | No | Maximum number of records to return |
| offset | Integer | No | Number of records to skip before returning |

**Output:**
```json
{
  "record_count": 10,
  "records": [
    {
      "field1": "value1",
      "field2": "value2"
    }
  ]
}
```

| **Field** | **Description** |
|-----------|-----------------|
| record_count | Number of records returned |
| records | The records themselves |

---

## 9. POST /pipeline

**Purpose:** Performs processing and storage together in a single request. This is the recommended endpoint for most use cases, since it removes the need to call `/process` and `/store` separately.

**Input:**
```json
{
  "records": [
    {
      "field1": "value1",
      "field2": "value2"
    }
  ],
  "profile_name": "company_financials",
  "table_name": "my_table"
}
```

| **Parameter** | **Type** | **Required** | **Description** |
|---------------|----------|--------------|-----------------|
| records | List of objects | Yes | Records to process and store |
| profile_name | String | Yes | Processing profile to apply |
| table_name | String | Yes | Name of the table where the result should be stored |

**Output:**
```json
{
  "row_count": 10,
  "columns": ["column1", "column2", "column3"],
  "rows_written": 10,
  "table_name": "my_table"
}
```

| **Field** | **Description** |
|-----------|-----------------|
| row_count | Number of rows in the result |
| columns | List of column names in the result |
| rows_written | Number of rows written to the table |
| table_name | Name of the table that was used |

## 10. Error Handling

Every endpoint follows the same error reporting pattern.

| **Status Code** | **Category** | **Description** |
|-----------------|--------------|-----------------|
| 422 | Validation Error | Request is missing required information or information is in the wrong format |
| 400 | Data Error | Request is properly formatted but rejected due to data-related issue (e.g., profile does not exist, empty record list) |
| 500 | Internal Error | Unexpected internal error occurred |

**Error Response Format:**
```json
{
  "detail": "Clear description of the problem"
}
```

---

## 11. Error Scenarios

| **Endpoint** | **Error Scenario** | **Status Code** |
|--------------|-------------------|-----------------|
| POST /process | Invalid profile name | 400 |
| POST /process | Empty records list | 400 |
| POST /validate | Invalid rule structure | 422 |
| POST /store | Empty records list | 400 |
| GET /retrieve | Table does not exist | 400 |
| POST /pipeline | Invalid profile name | 400 |
| POST /pipeline | Empty records list | 400 |
| POST /pipeline | Empty table name | 400 |

## 12. Known Limitations

| **#** | **Limitation** | **Description** |
|-------|----------------|-----------------|
| 1 | No Authentication | There is currently no authentication on any endpoint. Any system able to reach the server can call every endpoint without restriction. |
| 2 | Single Database File | The database used by `/store` and `/retrieve` is a single fixed file rather than a configurable connection. |
| 3 | Predictive Analytics Not Exposed | Forecasting functions are not currently exposed through any endpoint and are not part of this API. |
