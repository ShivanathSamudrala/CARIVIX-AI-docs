## 1. Overview

The CARIVIX AI Geospatial Service exposes three endpoints for retrieving Telangana district boundaries, performing attribute-based district lookups, and querying hydrology features within a spatial bounding box. All endpoints return GeoJSON in EPSG:4326 and are backed by PostGIS spatial indexing.

---

## 2. Service Overview

| **Field** | **Details** |
|-----------|-------------|
| Base URL (Feature Server) | `http://localhost:9000` |
| Base URL (FastAPI Layer) | `http://localhost:8000/api/v1/gis` |
| Coordinate Reference System | EPSG:4326 (WGS 84) |
| Default Response Format | GeoJSON (application/geo+json) / JSON (application/json) |
| Underlying Database | PostgreSQL 18 with PostGIS (`telangana_gis` / `gis_service`) |

## 3. Endpoint 1: District Boundaries FeatureCollection

### 3.1 Endpoint Details

| **Field** | **Details** |
|-----------|-------------|
| **Path** | `/collections/gis_service.TELANGANA_DISTRICTS/items` |
| **Alternate Path** | `/api/v1/gis/districts/geojson` |
| **Purpose** | Retrieves the administrative boundaries of all 33 Telangana districts formatted as a unified GeoJSON FeatureCollection |

### 3.2 Query Parameters

| **Parameter** | **Type** | **Required** | **Description** |
|---------------|----------|--------------|-----------------|
| limit | integer | Optional | Maximum features to return. Default: 50 |
| bbox | string | Optional | Spatial bounding-box filter in `minx,miny,maxx,maxy` format |

### 3.3 Underlying SQL Query

```sql
SELECT json_build_object(
  'type', 'FeatureCollection',
  'features', json_agg(
    json_build_object(
      'type', 'Feature',
      'geometry', ST_AsGeoJSON(geom)::json,
      'properties', json_build_object(
        'district', "dtname",
        'state', "stname"
      )
    )
  )
) AS api_geojson_payload
FROM gis_service."TELANGANA_DISTRICTS";
```

### 3.4 Sample Response (200 OK)

```json
{
  "type": "FeatureCollection",
  "features": [
    {
      "type": "Feature",
      "geometry": {
        "type": "MultiPolygon",
        "coordinates": [[[[78.3356, 19.8835], [78.3350, 19.8841], ...]]]
      },
      "properties": {
        "district": "Adilabad",
        "state": "TELANGANA"
      }
    }
  ]
}
```

## 4. Endpoint 2: Administrative Pattern Filter & Proximity Lookup

### 4.1 Endpoint Details

| **Field** | **Details** |
|-----------|-------------|
| **Path** | `/api/v1/gis/districts/filter` |
| **Purpose** | Performs a dynamic, case-insensitive attribute search to return target district boundaries for prompt grounding |

### 4.2 Query Parameters

| **Parameter** | **Type** | **Required** | **Description** |
|---------------|----------|--------------|-----------------|
| name | string | Required | District search substring (e.g., Hyderabad, Rangareddy) |

### 4.3 Underlying SQL Query

```sql
SELECT "dtname" AS district_name, ST_AsGeoJSON(geom)::json AS geometry
FROM gis_service."TELANGANA_DISTRICTS"
WHERE "dtname" ILIKE :name;
```

### 4.4 Sample Response (200 OK)

```json
[
  {
    "district_name": "Hyderabad",
    "geometry": {
      "type": "MultiPolygon",
      "coordinates": [[[[78.4012, 17.3501], [78.4120, 17.3620], ...]]]
    }
  }
]
```

## 5. Endpoint 3: Spatial Bounding-Box Envelope Search

### 5.1 Endpoint Details

| **Field** | **Details** |
|-----------|-------------|
| **Path** | `/collections/gis_service.waterway_river_Telangana/items` |
| **Query String** | `?bbox=78.0,17.0,79.0,18.0` |
| **Purpose** | Leverages GiST spatial indexing (the `&&` operator) to extract linear transport and hydrology assets within a geographic bounding envelope |

### 5.2 Underlying SQL Query

```sql
SELECT "name" AS river_name, ST_AsGeoJSON(ST_Simplify(geom, 0.0001))::json AS simplified_geom
FROM gis_service."waterway_river_Telangana, India"
WHERE geom && ST_MakeEnvelope(78.0, 17.0, 79.0, 18.0, 4326);
```

### 5.3 Performance Benchmark

| **Metric** | **Result** |
|------------|------------|
| Query Execution | GiST Bitmap Index Scan |
| Execution Time | ~7.5 ms |
