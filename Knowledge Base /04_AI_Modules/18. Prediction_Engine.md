## 1. Overview

The CARIVIX Prediction Engine is the machine-learning component responsible for processing structured data and generating predictive results through trained ML models.

The Prediction Engine is separate from the CARIVIX AI Engine:

| Component | Focus Area |
|---|---|
| AI Engine | Natural-language processing, document intelligence, RAG, embeddings, vector retrieval, LLM-based responses |
| Prediction Engine | Structured input data, input validation, data preprocessing, feature preparation, trained ML models, model loading, model inference, prediction generation, API integration, prediction validation, model evaluation |

**Primary Workflow:**

```text
Input Data → Validation → Preprocessing → Feature Preparation → 
Model Service → ML Model → Inference → Prediction → API Response
```

---

## 2. Objectives and Scope

The Prediction Engine is designed to provide a reusable ML inference layer within CARIVIX.

**Main Objectives:**

- Receive structured prediction requests
- Validate incoming data
- Apply model-specific preprocessing
- Prepare model-compatible features
- Load trained ML models
- Execute model inference
- Generate prediction results
- Validate prediction outputs
- Return structured API responses
- Support multiple predictive models
- Provide a clear separation between API and model logic
- Support testing and model-performance evaluation

**Processing Scope:**
The Prediction Engine covers the complete lifecycle from an incoming prediction request to the final prediction response.

---

## 3. Overall Architecture

The Prediction Engine consists of the following major layers:

| # | Layer |
|---|---|
| 1 | FastAPI API Layer |
| 2 | Prediction Request Layer |
| 3 | Input Validation |
| 4 | Data Preprocessing |
| 5 | Feature Preparation |
| 6 | Model Service |
| 7 | Trained ML Model |
| 8 | Inference |
| 9 | Prediction Processing |
| 10 | Output Validation |
| 11 | API Response |

**Primary Technical Architecture:**

```text
CARIVIX Application → FastAPI API Layer → Prediction Engine → 
Input Validation → Data Preprocessing → Feature Preparation → 
Model Service → Trained ML Model → Model Inference → 
Prediction Result → Output Validation → Structured API Response
```

---

## 4. Prediction Input and Validation

The Prediction Engine receives structured information from the application through the API layer. The validation layer verifies that the incoming data meets the expected model requirements.

**Validation Includes:**

- Required-field validation
- Data-type validation
- Missing-value detection
- Input-format validation
- Range validation where applicable
- Feature availability
- Input consistency

**Validation Flow:**

```text
Prediction Request → Schema Validation → Valid Input → Preprocessing
```

**If the Input is Invalid:**

```text
Prediction Request → Validation → Error → API Response
```

This prevents malformed input from reaching the ML model.

---

## 5. Data Preprocessing

After successful validation, the Prediction Engine prepares the data for ML inference. Preprocessing depends on the model and the dataset used during training.

**Typical Preprocessing Operations:**

- Missing-value handling
- Data-type conversion
- Data cleaning
- Numerical transformation
- Categorical transformation
- Scaling or normalization where required
- Feature formatting
- Invalid-value handling

**Key Requirement:** Maintaining consistency between training-time preprocessing and inference-time preprocessing.

**Preprocessing Flow:**

```text
Raw Input → Validation → Cleaning → Transformation → Encoding/Scaling → Processed Data
```

The resulting data must match the representation expected by the trained model.

---

## 6. Feature Preparation and Model-Ready Input

After preprocessing, the Prediction Engine prepares the final feature representation.

**This Stage Ensures:**

- Required features are available
- Features are in the expected order
- Feature types are correct
- Feature dimensions are correct
- Required transformations have been applied
- The resulting input matches the trained model's expected format

**Feature Preparation Flow:**

```text
Validated Input → Preprocessed Data → Required Features → 
Feature Transformation → Model-Compatible Input
```

This stage is important because even a correctly trained model can produce incorrect results if inference features do not match the training representation.

---

## 7. Model Service Architecture

The Model Service provides the abstraction layer between the Prediction Engine and the trained ML models. Instead of allowing FastAPI to directly manage individual model files and inference logic, the Prediction Engine communicates with the Model Service.

**Model Service Responsibilities:**

- Load trained models
- Manage model references
- Prepare model inputs
- Execute inference
- Return model outputs
- Handle model-specific inference logic
- Provide a reusable interface for additional models

**Architecture:**

```text
FastAPI → Prediction Engine → Model Service → ML Model
```

This separation reduces coupling and makes future model integration easier.

## 8. Trained ML Models and Predictive Workflows

The Prediction Engine integrates trained machine-learning models developed for CARIVIX predictive use cases.

**Documented Predictive Model Work:**

| Model | Approach | Documented Metric |
|---|---|---|
| Crisis Severity Prediction | XGBoost-based classification | ~96.37% accuracy |
| Crisis Risk Score | Ensemble-based regression | R² ≈ 0.9997 |

**Model Descriptions:**

- **Crisis Severity Prediction:** Classifies or estimates crisis severity based on the structured features supplied to the model.
- **Crisis Risk Score:** Generates a numerical risk-score prediction from structured input data.

**Note:** These metrics represent the documented evaluation results for the respective model-development datasets and evaluation methodology. They should not be interpreted as guaranteed production performance.

---

## 9. Model Loading and Inference

The Model Service manages access to the trained model.

**Inference Sequence:**

| Step | Action |
|---|---|
| 1 | Prediction request is received |
| 2 | Input is validated |
| 3 | Data is preprocessed |
| 4 | Features are prepared |
| 5 | Model Service identifies the required model |
| 6 | The trained model is loaded or accessed |
| 7 | Model-ready features are passed to the model |
| 8 | The model performs inference |
| 9 | Raw model output is returned |
| 10 | Output is processed into the required prediction format |

**Inference Flow:**

```text
Prediction Request → Validation → Preprocessing → Feature Preparation → 
Model Service → Trained Model → Inference → Raw Model Output → Prediction Result
```

The inference layer is responsible for executing the trained model without retraining it during a normal prediction request.

---

## 10. Prediction Generation and Response Processing

The raw output generated by the ML model is converted into a meaningful prediction result.

**Depending on the Model, the Output Can Represent:**

- Classification result
- Severity category
- Risk score
- Regression value
- Probability
- Numeric prediction
- Model-specific output

**Prediction Processing Flow:**

```text
Model Output → Output Processing → Prediction Validation → 
Prediction Formatting → API Response
```

The Prediction Engine therefore separates model output from the final application response.

FastAPI provides the API interface through which the Prediction Engine is accessed.

**API Layer Responsibilities:**

- Receiving prediction requests
- Validating request schemas
- Calling the Prediction Engine
- Handling API-level errors
- Returning prediction responses

**Prediction Engine Responsibilities:**

- Preprocessing
- Feature preparation
- Model selection
- Model inference
- Prediction generation

**Integration Relationship:**

```text
CARIVIX Application → FastAPI → Prediction Engine → Model Service → 
ML Model → Prediction → FastAPI → Application
```

This separation allows the API layer and ML processing layer to evolve independently.

## 15. Current Implementation and Conclusion

**Current Prediction Engine Scope:**

The CARIVIX Prediction Engine provides a structured ML inference architecture covering:

- FastAPI integration
- Prediction request handling
- Input validation
- Data preprocessing
- Feature preparation
- Model Service
- Trained ML model integration
- Model loading
- ML inference
- Prediction generation
- Output validation
- Error handling
- API response generation
- Model testing
- Model evaluation

**Complete Prediction Architecture:**

```text
Structured Input → FastAPI → Validation → Preprocessing → Feature Preparation → 
Model Service → Trained ML Model → Inference → Prediction → 
Output Validation → API Response
```

**Conclusion:**

The CARIVIX Prediction Engine provides the dedicated machine-learning prediction layer of the platform. Its architecture separates the API, preprocessing, model-management, and inference responsibilities into clear components. The Model Service acts as the connection between the Prediction Engine and trained ML models, allowing multiple predictive models to be integrated without tightly coupling them to the API.

The documented predictive implementations include Crisis Severity using an XGBoost-based approach and Crisis Risk Score using an ensemble regression approach.

The Prediction Engine therefore establishes a reusable foundation for structured-data prediction, model integration, inference, validation, evaluation, and future expansion of CARIVIX predictive capabilities.
