## 1. Overview

The CARIVIX Voice Architecture provides a voice-based interface through which users can interact with the CARIVIX platform using natural language. The architecture accepts voice input, converts speech into text, identifies the user's intent, extracts required parameters, and routes the request to the appropriate CARIVIX module.

## 3. Voice Processing Components

### 3.1 Audio Dataset Preparation

| Step | Description |
|---|---|
| Dataset Collection | Voice-command datasets collected and loaded |
| Metadata Generation | Automatically generated for all audio files |
| Category Identification | Dataset categories and languages identified |
| Format Standardization | Audio files processed into a common format |

### 3.2 Audio Preprocessing

The voice pipeline standardizes audio to:

| Parameter | Value |
|---|---|
| Sampling Rate | 16 kHz |
| Channel | Mono |
| Format | Processed WAV audio |

### 3.3 Speech-to-Text

The main CARIVIX STT model is a fine-tuned Whisper Small model.

The notebook includes:

- Whisper processor
- Whisper model
- Feature extraction
- Tokenization
- Seq2Seq training
- Model evaluation
- Model saving/loading
- Inference testing

### 3.4 Multilingual Recognition

The implementation tests:

| Language | Status |
|---|---|
| English |  Supported |
| Hindi |  Supported |
| Telugu | Supported |

The multilingual recognition function supports language-specific Whisper decoding prompts.

## 8. Architecture Summary

CARIVIX currently follows a unified text-and-voice NLP architecture. Text queries enter the NLP pipeline directly, while voice commands first pass through audio preprocessing and the fine-tuned Whisper Speech-to-Text model.

Both inputs are subsequently converted into text and processed through the same NLP layer consisting of preprocessing, intent classification, and entity extraction. The resulting structured query provides the intent, entities, and relevant context required by downstream CARIVIX intelligence modules.

> **Key Architecture Principle:** Voice and text inputs share the same NLP understanding layer, rather than requiring two separate intent/entity processing systems.
