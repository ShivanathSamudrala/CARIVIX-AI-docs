## 1. Overview

This document captures how a spatial request moves through the CARIVIX AI stack from the map UI, through the FastAPI intent router and pg_featureserver, into PostgreSQL/PostGIS, and back out again as a simplified GeoJSON layer. Two views are provided: a system-level architecture diagram and a step-by-step sequence diagram of a single bounding-box query.

---

## 2. Diagram 1 – System Architecture

Traces a request from the CARIVIX frontend map UI through the FastAPI intent router and pg_featureserver, into the PostgreSQL/PostGIS engine, through the spatial processing pipeline (bounding-box filtering, geometry simplification, and GeoJSON serialization), and back to the map UI as a rendered layer.

**End-to-end CARIVIX AI & GIS service architecture.**

### 2.1 Layer Summary

| **Layer** | **Description** |
|-----------|-----------------|
| 01 Client & Interface Layer | User prompt or map viewport bbox originates in the CARIVIX frontend |
| 02 API & Routing Layer | FastAPI intent router forwards the filter request to pg_featureserver (Docker, port 9000) |
| 03 Database Layer | PostgreSQL 18 / PostGIS engine, scoped to the `gis_service` schema under a least-privilege `telangana_user` role |
| 04 Processing Layer | `ST_MakeEnvelope` bounding-box filter, `ST_Simplify` vertex reduction, and `ST_AsGeoJSON` serialization |
| 05 Response | A clean GeoJSON FeatureCollection is returned to the gateway and rendered as a map layer |

## 3. Diagram 2 – Query Lifecycle

### 3.1 Request Layer Data (BBox: 78.0, 17.0, 79.0, 18.0)

**Geospatial Query Lifecycle & Simplification Pipeline**

### 3.2 Step-by-Step

| **Step** | **Action** |
|----------|------------|
| 01 | **Request layer data** – UI/agent sends bbox `78.0, 17.0, 79.0, 18.0` to the API |
| 02 | **Execute bounding envelope query** – API calls PostGIS with `ST_MakeEnvelope` |
| 03 | **Evaluate spatial intersection** – PostGIS hands off to the GiST spatial index (`geom && envelope`) |
| 04 | **Return matched pointers** – Index responds in ~7.5 ms via a bitmap scan |
| 05 | **Apply `ST_Simplify(geom, 0.0001)`** – Vertex count drops 57–86% |
| 06 | **Aggregate to FeatureCollection** – `ST_AsGeoJSON` builds the payload |
| 07 | **Stream GeoJSON payload** – PostGIS returns data to the API in ~111 ms total |
| 08 | **Deliver map layer** – API hands the lightweight EPSG:4326 vector layer back to the UI |
