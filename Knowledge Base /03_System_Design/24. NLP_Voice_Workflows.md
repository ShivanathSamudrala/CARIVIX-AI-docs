## 1. Overview

The CARIVIX NLP and Voice Workflows process user input through a unified pipeline that converts raw text or spoken commands into a structured representation containing processed text, predicted intent, and extracted entities.

**The NLP and Voice Workflows Are:**

1. NLP Workflow (Text Input)
2. Voice NLP Workflow (Voice Input)

---

## 2. NLP Workflow

The CARIVIX NLP module processes a user query through a sequential NLP pipeline. The workflow converts the raw query into a structured representation containing the processed text, predicted intent, and extracted entities.

### NLP Processing Flow

```
User Query
    ↓
Text Preprocessing
    ↓
Tokenization / Normalization
    ↓
TF-IDF Feature Representation
    ↓
Intent Classification
    ↓
Entity Extraction
    ↓
Entity & Intent Mapping
    ↓
Structured Query Output
    ↓
CARIVIX Intelligence / Data Module
```

### Step-by-Step Processing

**Step 1: User Query Input**

The system accepts a natural-language query from the user.

**Example:**

> "Analyze Microsoft's revenue growth in Hyderabad during 2025."

**Step 2: Text Preprocessing**

The query is passed through the existing preprocessing pipeline to normalize the input and prepare it for NLP processing.

**Step 3: Intent Classification**

The project contains a CARIVIX intent classification dataset and an ML-based intent classifier.

**Implemented Classifier Uses:**

- TF-IDF Vectorizer
- Unigram and bigram features
- Logistic Regression
- Train/test split with stratification
- Accuracy, precision, recall, and F1 evaluation

**The classifier maps the query to a CARIVIX intent such as:**

- Business Intelligence
- Economic Analysis
- Smart City Analysis
- GIS Queries
- Prediction
- Research Queries
- Report Generation
- Visualization
- Question Answering
- Monitoring
- User Management
- Conversation
- General Navigation

**Step 4: Entity Extraction**

The query is then analyzed for relevant entities.

**The implemented CARIVIX entity processing handles:**

- Locations
- Organizations
- Dates
- Metrics
- Categories

spaCy NER is used as a base, with additional CARIVIX-specific keyword/entity handling.

**Step 5: Structured Output**

The final NLP pipeline produces a structured result:

- Original Query
- Processed Query
- Predicted Intent
- Extracted Entities

**Example:**

| Field | Value |
|---|---|
| Query | Analyze Microsoft's revenue growth in Hyderabad during 2025 |
| Intent | Business Intelligence |
| Entities | Microsoft → Organization, Hyderabad → Location, 2025 → Date, Revenue → Metric |

## 3. Voice NLP Workflow

The voice workflow converts spoken commands into text and then sends the recognized command into the NLP processing pipeline.

### Voice Processing Flow

```
User Voice Command
    ↓
Audio Recording
    ↓
Audio Preprocessing
    ↓
16 kHz Mono Audio
    ↓
Whisper Speech-to-Text
    ↓
Transcribed Text
    ↓
NLP Preprocessing
    ↓
Intent Classification
    ↓
Entity Extraction
    ↓
Structured Command
    ↓
CARIVIX Action / Intelligence Module
```

### Voice Processing Components

**Audio Dataset Preparation:**

- Voice-command datasets were collected/loaded
- Metadata was generated automatically
- Dataset categories and languages were identified
- Audio files were processed into a common format

**Audio Preprocessing:**

The voice pipeline standardizes audio to:

- 16 kHz sampling rate
- Mono channel
- Processed WAV audio

**Speech-to-Text:**

The main CARIVIX STT model is a fine-tuned Whisper Small model.

The notebook includes:

- Whisper processor
- Whisper model
- Feature extraction
- Tokenization
- Seq2Seq training
- Model evaluation
- Model saving/loading
- Inference testing

**Multilingual Recognition:**

The implementation tests:

- English
- Hindi
- Telugu

The multilingual recognition function supports language-specific Whisper decoding prompts.

## 8. Architecture Summary

CARIVIX currently follows a unified text-and-voice NLP architecture. Text queries enter the NLP pipeline directly, while voice commands first pass through audio preprocessing and the fine-tuned Whisper Speech-to-Text model.

Both inputs are subsequently converted into text and processed through the same NLP layer consisting of preprocessing, intent classification, and entity extraction. The resulting structured query provides the intent, entities, and relevant context required by downstream CARIVIX intelligence modules.

> **Key Architecture Principle:** Voice and text inputs share the same NLP understanding layer, rather than requiring two separate intent/entity processing systems.
