## 1. Overview

The CARIVIX data processing workflow is a structured, multi-stage pipeline that transforms raw data into actionable intelligence. It is designed to be robust, scalable, and maintainable, ensuring data quality and reliability at every stage.

---

## 2. High-Level Workflow

The pipeline follows a linear progression from data acquisition to final visualization and storage.
Data Acquisition → Data Validation → Error Handling → Data Transformation →
Predictive Analytics / NLP Processing → Database Storage → Visualization

---

## 3. Stage 1: Data Acquisition

The workflow begins with acquiring data from diverse sources.

### 3.1 Supported Sources

| **Source** | **Format** | **Method** |
|------------|------------|------------|
| Local Files | CSV, Excel, JSON | `import_csv()`, `import_excel()`, `import_json()` |
| REST APIs | JSON | `fetch_api_data()` with retry & pagination |
| Streaming | N/A | (Planned for future) |

### 3.2 Configuration

- All source configurations (paths, endpoints, credentials) are stored in a central `config.yaml` file.
- The **`get_importer()`** function selects the correct importer based on the `source_type` in the config.

### 3.3 Output

- Each importer returns a **standardized Pandas DataFrame**, ensuring uniform data structure for downstream layers.

---

## 4. Stage 2: Data Validation & Error Handling

### 4.1 Validation with `DataValidator`

- **`DataValidator.validate(df)`**:
    1.  **Schema Check**: Verifies column presence, data types, and required fields.
    2.  **Rule Check**: Applies column-specific rules (min/max values, allowed lists).
    3.  **Quality Check**: Detects missing values and duplicate records.
    4.  **Reporting**: Returns a detailed validation report highlighting all issues.

- **`DataValidator.clean(df)`**:
    - Cleans the DataFrame by removing or imputing invalid data based on the validation rules.

### 4.2 Robust Error Handling

The pipeline is designed to be resilient to errors, ensuring a single bad record does not halt the entire process.

| **Mechanism** | **Description** | **Purpose** |
|---------------|-----------------|-------------|
| Custom Exceptions | Specific error types (e.g., `ValidationError`, `DataFetchError`) | Improves error diagnosis |
| `safe_run()` Decorator | Retries failed functions with exponential backoff | Handles transient failures |
| `ErrorCollector` | Collects all errors during a run | Allows processing to continue and provides a comprehensive error log |

---

## 5. Stage 3: Data Transformation

This is the core of the processing pipeline, where raw data is converted into an analysis-ready format.

### 5.1 Transformation Engine

- **`DataProcessingEngine.run(df, ...)`** orchestrates the entire transformation process.

### 5.2 Transformation Steps

| **Step** | **Description** | **Implementation** |
|----------|-----------------|-------------------|
| **Data Cleaning** | Standardizes text, removes special characters, trims whitespace | Vectorized Pandas operations |
| **Normalization** | Scales numeric data (e.g., Min-Max, Z-Score) | `sklearn.preprocessing` |
| **Feature Engineering** | Creates new features from existing data (e.g., ratios, date parts) | Custom functions |
| **Encoding** | Converts categorical data to numeric form (One-Hot, Label Encoding) | `pandas.get_dummies()`, `sklearn.preprocessing` |

### 5.3 Performance Optimization

- **Vectorized Operations**: Pandas/Numpy vectorization replaces slow loops.
- **Memory Optimization**: Uses data types like `int32` and `float32`.
- **Chunked Reading**: Handles large files in chunks.
- **Multiprocessing**: Enables parallel processing for heavy tasks.

### 5.4 Output

The processed data is saved in **Parquet** format for efficient storage and faster I/O. CSV is also available as an alternative.

---

## 6. Stage 4: Analytics Layer

The workflow branches here, with data being routed to either Predictive Analytics or NLP processing.

### 6.1 Predictive Analytics

- **Current State**: A set of helper functions for forecasting (`arima_forecast`, `prophet_forecast`, etc.) are available. The model selection layer is pending.
- **Future**: A model selection layer will automatically choose the best model based on the use case.

### 6.2 NLP Helpers

- **Current State**: Lightweight versions of sentiment analysis, entity extraction, topic modeling, and text classification.
- **Future**: These will be upgraded to transformer-based models without impacting other modules.
