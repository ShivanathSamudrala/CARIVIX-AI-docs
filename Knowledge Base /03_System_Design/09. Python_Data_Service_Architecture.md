## 1. Overview

The Python backend of CARIVIX is architected as a complete, modular pipeline that handles the entire data lifecycle from acquisition to visualization. The system is built with a clear separation of concerns, ensuring maintainability, scalability, and ease of future enhancements.

The architecture consists of five core layers, each with specific responsibilities and well-defined interfaces.

---

## 2. Architecture Layers

### 2.1 Data Acquisition Layer

The Data Acquisition Engine is responsible for ingesting data from various sources and presenting it in a unified format to the rest of the pipeline.

| **Source Type** | **Status** | **Key Features** |
|-----------------|------------|------------------|
| CSV Files |  Built & Verified | Standardized reading with type inference |
| Excel Files (.xlsx, .xls) |  Built & Verified | Handles multiple sheets and complex formatting |
| JSON Files |  Built & Verified | Supports nested structures and arrays |
| REST APIs |  Built & Verified | Handles authentication, pagination, retries |

#### Key Components

- **`get_importer(category, config, source_name)`**: Factory function that selects the correct importer based on the source type.
- **Unified Interface**: Every importer implements a standard `load()` method, ensuring the rest of the backend does not need to know the source's origin.
- **Configuration**: All data sources are managed via a centralized YAML config file, allowing new sources to be added without code changes.

### 2.2 Data Processing Layer

This layer handles validation, error handling, transformation, and performance optimization of the raw data.

#### Validation

- **Purpose**: To ensure incoming data meets quality and structure requirements before processing.
- **Implementation**: The `DataValidator` class provides two key methods:
    - `validate(df)`: Performs schema-based checks (data types, required fields, min/max values, allowed values) and returns a validation report.
    - `clean(df)`: Returns a cleaned dataframe based on the validation rules.

#### Error Handling

- **Purpose**: To ensure pipeline resilience, preventing single-point failures from stopping the entire process.
- **Implementation**:
    - **Custom Exceptions**: Specific error types for different failure scenarios.
    - **`safe_run()` Decorator**: Retries failed functions with exponential backoff.
    - **`ErrorCollector`**: Aggregates errors during a processing run without halting at the first bad record.

#### Transformation

- **Purpose**: To convert raw data into a structured, analysis-ready format.
- **Implementation**: The `DataProcessingEngine.run(df, ...)` method orchestrates the entire transformation workflow, including:
    - Data cleaning
    - Normalization
    - Feature engineering
    - Encoding
- **Output**: Processed data can be saved in Parquet or CSV format.

#### Performance Optimization

The system employs several strategies to handle large datasets efficiently:
- **Vectorized Operations**: Uses Pandas/Numpy vectorization instead of row-by-row loops.
- **Memory Optimization**: Uses memory-efficient data types (e.g., `int32`, `float32`).
- **Chunked Reading**: Processes large files in manageable chunks.
- **Multiprocessing**: Optional parallel processing for computationally intensive tasks.
