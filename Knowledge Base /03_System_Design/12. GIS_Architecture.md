## 1. Overview

The Geographic Information System (GIS) architecture of CARIVIX AI provides a complete spatial data management and visualization solution. It combines a robust backend spatial database (PostGIS), a lightweight and high-performance frontend mapping engine (Leaflet.js), and a seamless API layer to enable interactive geospatial intelligence.

The architecture is designed to handle large-scale vector and raster datasets, support multi-scale administrative hierarchies, and deliver fast, responsive map visualizations for urban planning, infrastructure monitoring, and location-based analytics.

---

## 2. System Architecture Overview

The GIS module acts as the spatial data layer that feeds coordinate boundaries and location context into backend models, analytics dashboards, and voice/NLP navigation components.

## 3. Core Components

### 3.1 Spatial Data Layer (PostgreSQL/PostGIS)

The permanent spatial database serves as the single source of truth for all GIS data.

| **Component** | **Details** |
|---------------|-------------|
| Database Name | `telangana_gis` |
| Spatial Extension | PostGIS |
| CRS | EPSG:4326 – WGS 84 |
| Access Role | `telangana_user` (least-privilege) |
| Tables | 16 project tables (boundaries, roads, hydrology, population) |

### 3.2 Backend GIS Services (Python)

| **Component** | **Purpose** |
|---------------|-------------|
| GeoPandas | Spatial data manipulation and analysis |
| Shapely | Geometric operations (point-in-polygon, intersections) |
| FastAPI | REST API endpoints for spatial queries |
| SQLAlchemy | Database ORM and connection management |

### 3.3 Frontend Visualization (Leaflet.js)

| **Component** | **Purpose** |
|---------------|-------------|
| Leaflet.js | Lightweight, mobile-friendly interactive maps |
| CARTO Light | Base map tile service |
| Leaflet.heat | Kernel density heatmap generation |
| Leaflet.markercluster | Marker clustering for large point datasets |
| HTML5 Canvas | Optimized vector rendering (preferCanvas: true) |

### 3.4 Geospatial Data Processing Workflow

The GIS module ingests, validates, and processes spatial data through a structured pipeline:

| **Stage** | **Description** |
|-----------|-----------------|
| 1. Data Ingestion | GeoJSON boundaries, GADM shapefiles, OSM features |
| 2. Validation | Attribute table validation, completeness check (33 districts) |
| 3. Standardization | Spatial reference standardization, CRS assignment (EPSG:4326) |
| 4. Processing | Spatial queries (ST_Contains), joins, aggregations |
| 5. Storage | Migration to permanent PostGIS database |
| 6. Visualization | Vector polygon overlays, heatmaps, choropleth styling |

## 4. Data Sources & Acquisition

### 4.1 Administrative Boundaries (GADM v4.1)

| **Layer** | **Description** |
|-----------|-----------------|
| gadm41_IND_0 | National boundary of India |
| gadm41_IND_1 | State-level boundaries |
| gadm41_IND_2 | District-level boundaries |
| gadm41_IND_3 | Sub-district boundaries |
| TELANGANA_DISTRICTS | Authoritative 33-district layer (primary) |

### 4.2 OpenStreetMap Features (via QuickOSM)

| **Key** | **Value** | **Resulting Layer** |
|---------|-----------|---------------------|
| natural | water | natural_water_Telangana |
| waterway | river | waterway_river_Telangana |
| highway | motorway | highway_motorway_Telangana |
| highway | trunk | highway_trunk_Telangana |
| highway | primary | highway_primary_Telangana |
| highway | secondary | highway_secondary_Telangana |

### 4.3 Population Data

- **Format:** CSV (district_name, population)
- **Join Field:** district_name → dtname (TELANGANA_DISTRICTS)
- **Storage:** Non-spatial attribute table (telangana_population)

### 5.3 Population Choropleth

- **Classification:** Graduated (choropleth) with sequential colour ramp
- **Ramp:** Oranges / YlOrRd
- **Method:** Natural Breaks (Jenks)
- **Expression:** `to_int(replace("telangana_population_population", ',', ''))`
