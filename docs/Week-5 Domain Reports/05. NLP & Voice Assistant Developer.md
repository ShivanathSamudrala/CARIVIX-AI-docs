## 1. Overview

Week 5 focused on strengthening the **CARIVIX AI Natural Language Processing (NLP) and Voice Assistant pipeline** by improving intent classification, entity extraction, query normalization, ambiguity handling, structured request generation, and backend/data-service connectivity.

The work progressed from **NLP pipeline review and query-category finalization** to **dataset expansion, model evaluation, entity validation, natural-language query processing, backend integration, and end-to-end testing**.

The sprint established a functional workflow for converting natural-language user queries into structured requests that can be processed by downstream CARIVIX backend and data services.

The evaluation also provided measurable performance results and identified specific areas for further improvement, particularly around **intent overlap, entity false positives, ambiguous queries, and multilingual evaluation**.

| **Metric** | **Value** |
|--------------|-------------:|

The realistic-query evaluation produced a lower accuracy compared with the held-out dataset, highlighting the impact of natural-language variation and semantic overlap between certain CARIVIX intent categories.

| **#** | **Observed Confusion** |
|------:|----------------------------|
| 1 | Report Generation → Economic Analysis |
| 2 | Visualization → Business Intelligence |
| 3 | Monitoring → Smart City Analysis |

These overlaps indicate areas where additional training examples, contextual features, and intent-disambiguation logic may improve classification performance.

## 6. Entity Extraction & Validation

The NLP pipeline was enhanced to extract important entities from user queries and make them available for downstream processing.

### Entity Types

| **Entity Type** | **Examples / Purpose** |
|--------------------|----------------------------|
| Locations | Cities, regions, geographic areas |
| Metrics | Economic, business, operational, or analytical metrics |
| Organizations | Companies, institutions, government organizations |
| Dates / Time Periods | Years, dates, quarters, time ranges |
| Categories | Domain-specific classification information |

### Entity Validation Results

| **Metric** | **Value** |
|--------------|-------------:|
| Precision | **75.86%** |
| Recall | **100.00%** |
| F1 Score | **86.27%** |

The entity extraction evaluation achieved **100% recall**, indicating that the evaluated target entities were successfully identified, while the lower precision indicates the presence of additional or overlapping entity detections.

### Observed Entity Extraction Issues

- Detection of both **"GDP"** and **"GDP growth"** as separate entities
- Detection of **"traffic"** along with **"traffic congestion"**
- Additional text being included as part of organization or location entities
- Unwanted category detections in some queries
- Overlapping metric extraction in certain natural-language queries

These findings provide specific areas for entity-boundary refinement and improved extraction rules or model behavior.

## 7. Query Normalization

A query normalization layer was implemented to provide consistent input to the intent-classification and entity-extraction stages.

### Normalization Features

| **Feature** | **Description** |
|---------------|----------------------|
| Lowercase Conversion | Converts input queries into lowercase text |
| Contraction Expansion | Expands common contractions |
| Punctuation Removal | Removes unnecessary punctuation |
| Whitespace Normalization | Standardizes whitespace |
| Standardized Preparation | Prepares queries for consistent NLP processing |

### Processing Objective

The normalization stage reduces unnecessary textual variation and establishes a standardized representation of user input before intent classification and entity extraction.

## 8. Ambiguity Handling

The NLP module includes basic ambiguity detection for queries where important contextual information is missing.

### Contextual Information Checked

- Company or organization
- Location
- Year or time period
- Other required contextual information

When required information is unavailable, the system identifies the query as potentially ambiguous and determines when additional clarification may be required.

This provides a foundation for future conversational clarification workflows within the CARIVIX Voice and NLP experience.

## 9. Natural-Language to Structured Request Conversion

The NLP pipeline converts a natural-language user query into structured information for downstream CARIVIX services.

### Structured Request Components

```text
Original User Query
        ↓
Processed Query
        ↓
Predicted Intent
        ↓
Extracted Entities
        ↓
Structured Request
        ↓
Backend / Data Service
```

The structured representation provides downstream services with the information required to process the user's request without requiring direct interpretation of the original natural-language query.
